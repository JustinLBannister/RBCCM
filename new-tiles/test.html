Why this design works better

01

Whole-card clickable via a single stretched link

The title anchor's ::before pseudo covers the entire card, so any click that isn't on an interactive control (Listen, Save, Share, More) navigates to the article. Screen readers announce one link per card instead of three; right-click and open-in-new-tab work anywhere on the card, not just on the title.

02

Progressive disclosure keeps the primary card clean

Podcast platform choices, share targets, and "More" options only render when the user asks. The default card shows just the four essential actions (Listen · Save · Share · More), reducing visual noise and cognitive load at scan time. The popover expands in place with a smooth grid-row transition so nothing shifts.

03

Focus stays clear while everything else dims

When a popover opens, a scrim darkens the rest of the card at 30% opacity while the popover and its anchor row stay bright. Stacking context is isolated (isolation: isolate) so the effect can't leak into sibling cards. Users' eyes are pulled directly to the decision they're making.

04

Save persists across sessions without an account

The bookmark icon writes to localStorage, so a user can save a tile and see it restored the next time they visit — no login, no server round-trip, no privacy footprint. The icon swaps from outline to filled instantly and mirrors aria-pressed so assistive tech announces the state change.

05

Native share sheet where supported, explicit fallback elsewhere

Mobile Safari, iOS Chrome, and modern Android browsers all support navigator.share() — we surface the OS share sheet so users get their full app list. Desktop and older browsers get a curated fallback panel (Copy link · X · LinkedIn · Email) with the platforms our audience actually uses.

06

Player slides in from the bottom, doesn't hijack the page

Hitting play reveals a bottom-pinned Captivate iframe that overlays the viewport without disrupting scroll position or covering the card the user was reading. Escape or the close button dismisses it. Feels like an in-page media player, not a modal takeover.

07

Duration + topic tags let users decide before they click

The duration chip in the media overlay signals audio length upfront (podcast-app convention users already know). Topic tags at the bottom of the card body let people scan for relevant subjects without opening anything. Fewer wasted clicks, higher engagement rates.

08

Feed-driven content, author-controllable

Cards can auto-populate from the RBCCM insights RSS feed (see below — the 3 cards are pulled live from /en/insights/data/2026-insights) or the author can fill each tile manually via TeamSite Datums. Same component, both modes — no code change to switch.
